# SYMTRI bug audit

Goal: audit the public site, code, and persisted data; repair confirmed defects and verify the complete user flow. This is a bounded audit, not proof that all possible bugs have been eliminated.

## Database and security baseline

- Latest hourly ingestion and monitor were healthy. Source coverage was partial for Hugging Face, with other sources healthy.
- No invalid source URLs, empty titles, publication dates over one day in the future, malformed ready-note arrays, ready publication-revision mismatches, or expired working-note leases were found.
- Supabase's 24 “RLS enabled, no policy” notices correspond to server-only tables with normal row access denied. Legacy table-wide client privileges were subsequently found and revoked; adding public row policies would weaken the design.
- Mutable helper search paths are now fixed. The public vector extension is an advisory finding, not evidence of an exposed data path.
- Recent Vercel fatal/error scan returned no entries. Log retention prevents a full historical error scan.
- Public text is rendered through Markdown with raw HTML disabled and links transformed through the HTTP(S) URL validator. JSON-LD escapes script terminators. SQL request inputs are parameterized. Cron/maintenance writes require the configured bearer secret. Public client table/sequence grants were revoked by migration `20261013042527_revoke_legacy_client_grants`; the server accesses data through its own database connection. Source fetches validate and pin public DNS addresses.

## Production verification

- First repair release: `0be1910`, Ready on `symtri.com`. Full production health check passed with a healthy monitor, zero embedding/classification/catalog/graph backlogs, two topic pages, 20 connection sources, and two historical snapshots verified.
- First post-release sample: `/api/signals` 832 ms (baseline 16,296 ms), `/api/status` 1,695 ms (baseline 6,266 ms), topic list 133 ms, impossible snapshot date 400 in 107 ms. These are measured samples, not a latency guarantee.
- Production-build browser: 1440 px desktop, 756×469 short desktop, 390×844 mobile; header remains at top after source scrolling; Ask stays beside the map on short desktop; Escape restores Ask-trigger focus.
- Delayed snapshot retains the live header and original pending URL until saved data arrives. Failed snapshot retains the live feed and reports archive failure. Unavailable story clears its invisible selection and removes the signal URL parameter.
- Disabled-WebGL browser confirmed a null WebGL context; region browsing, source lists, and Ask remained usable without an application error page.

## Upstream advisory

The full dependency audit still flags the development-only `braces` parser and four packages that depend on it. [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) has no published patched version. Its installed path is Next's ESLint plugin → fast-glob → micromatch → braces; application routes do not pass visitor-controlled patterns to it. The runtime-only audit is clean. Forcing npm's suggested older Next/Workflow majors would break the application's platform and does not constitute a safe repair.
