# SYMTRI bug audit

Goal: audit the public site, code, and persisted data; repair confirmed defects and verify the complete user flow. This is a bounded audit, not proof that all possible bugs have been eliminated.

## Confirmed findings

| Finding | Evidence | Repair | Verification |
|---|---|---|---|
| Overview exceeds the client's 12-second deadline | Live `/api/signals` took 16.3 seconds; the overview ranked the full readable archive before applying its 300-item cap | Indexed per-source reservations plus a bounded recent candidate list; retain current publication checks | Query plan: 37 ms; local Postgres compares selected IDs against the full-ranking reference |
| Readable counts repeatedly probe the archive | Live EXPLAIN: 6,551 ms, 35,352 archive lookups, over 622,000 shared blocks | Materialize slim eligible events, published note IDs, and distinct active observations before joining | EXPLAIN: 654 ms, 126,207 blocks; old/new full-archive counts have no differences in one database snapshot |
| Status repeats note eligibility lookups | Production query statistics: mean 3,142 ms, max 10,874 ms | Join distinct active observation IDs once, materializing only queue-statistic columns | EXPLAIN: 401 ms; old/new results have no differences in one database snapshot |
| Header and Ask can move off-screen | After scrolling a source into view, `.experience.scrollTop` became 47 and the Ask trigger's top was -29 px | Use `overflow: clip` on the application frame; scrollable panels retain `overflow: auto` | Passed in isolated production-build browser |
| Historical deep link can label live data as a snapshot | Initial/popstate handlers set `selectedDay` before the snapshot response | Commit the displayed date only with the snapshot; retain the URL while a snapshot is pending | Passed in isolated production-build browser |
| Impossible dates reach Postgres date casts | History/storage validated only the string format, accepting February 30 | Shared calendar validation in History, Ask, storage, and navigation | Leap-day/invalid-date unit cases; isolated Postgres verifies invalid History and Ask return 400 |
| Unpublished shared story can remain selected invisibly | The signal lookup ignored an explicit `{event:null}` response | Clear an unavailable selection, preserve temporary-error behavior, bound the request | Passed in isolated production-build browser |
| Singular database question loses its named thread | Live Ask cited a coding-agent paper for “What is new in database research?” | Explicit database and programming-language aliases | Positive routing and negative source-selection unit cases |
| Topic catalog failure escapes the API error boundary | Catalog read preceded the route's `try` | Include catalog lookup in the guarded operation; keep error responses uncached | Local route/database checks |

## Database and security baseline

- Latest hourly ingestion and monitor were healthy. Source coverage was partial for Hugging Face, with other sources healthy.
- No invalid source URLs, empty titles, publication dates over one day in the future, malformed ready-note arrays, ready publication-revision mismatches, or expired working-note leases were found.
- Supabase's 24 “RLS enabled, no policy” notices correspond to server-only tables with normal row access denied. Legacy table-wide client privileges were subsequently found and revoked; adding public row policies would weaken the design.
- Mutable helper search paths are now fixed. The public vector extension is an advisory finding, not evidence of an exposed data path.
- Recent Vercel fatal/error scan returned no entries. Log retention prevents a full historical error scan.
- Public text is rendered through Markdown with raw HTML disabled and links transformed through the HTTP(S) URL validator. JSON-LD escapes script terminators. SQL request inputs are parameterized. Cron/maintenance writes require the configured bearer secret. Public client table/sequence grants were revoked by migration `20261013042527_revoke_legacy_client_grants`; the server accesses data through its own database connection. Source fetches validate and pin public DNS addresses.
