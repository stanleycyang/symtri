## Next.js review findings and resolution

### Sweeping 1/9 — Build and bundle optimization

**Findings: 1.** `demo/remotion/index.tsx` imported an undeclared package inside the application's TypeScript scope. Hosted CI failed with TS2307. Video tools also had no executable package scripts or lockfile. The demo is now an optional standalone package with pinned dependencies, its own typecheck, and a separate CI job. Application typecheck excludes that independent package; its typecheck is explicitly retained in CI.

### Sweeping 2/9 — Caching strategy

**Findings: 0.** Signal reads remain `no-store`. Retry work uses the same endpoint and does not fetch providers per visitor. RSS keeps its existing hourly cache. No database caching or persistence behavior changed.

### Sweeping 3/9 — Server components and data fetching

**Findings: 0.** No new server-component reads or shared-client database concurrency. The existing archive/preview boundary is preserved.

### Sweeping 4/9 — Routing and navigation

**Findings: 1.** `/favicon.ico` served a transparent one-pixel PNG from a custom handler. Replace it with a real multi-size ICO derived from `app/icon.svg`, using the installed Next.js metadata file convention. Camera and pointer navigation behavior remain intact.

### Sweeping 5/9 — Server actions and mutations

**Findings: 0.** No mutations, authentication changes, new server actions, or schema changes.

### Sweeping 6/9 — Streaming and loading states

**Findings: 1.** The new feed retry path allowed indefinite requests, overlapping visibility/interval/retry loads, and stale retry timers after success. A small refresh scheduler now permits one active request, retries four times with exponential delays and jitter, resets after success, pauses hidden tabs, and aborts scheduled work on cleanup. Exhaustion keeps manual recovery and the normal refresh interval. UI distinguishes automatic retry, unavailable evidence, and a measured quiet region.

### Sweeping 7/9 — Metadata and SEO

**Findings: 1.** RSS used the 1200px social preview as its channel image. The channel now references a 144px branded PNG with dimensions within the [RSS image specification](https://www.rssboard.org/rss-specification). The Atom self link already existed and remains intact.

### Sweeping 8/9 — Client components

**Findings: 0.** The map stays dynamically loaded with SSR disabled. No video tooling enters the application dependency graph or browser bundle. Initial loading state is deterministic; no new hydration-dependent render logic.

### Sweeping 9/9 — Codebase hygiene

**Findings: 1.** Raw footage was duplicated in both `demo/out/` and application `public/`, adding about 18 MB of unnecessary tracked files and publicly served raw assets. Raw recordings, palettes, render inputs, and optional package dependencies are now ignored. Only reviewed final exports remain tracked. Demo dependencies have their own grouped Dependabot updates.

Findings overlap categories rather than representing additional independent bugs:

- Refresh cleanup and single-flight behavior are covered by failure, visibility, recovery, and abort tests. Mobile count formatting is shared within the component; scene labels now show measured zero as quiet and exhausted initial loading as unavailable.
- Captions were always passed frame zero, and compositions created inline component functions. The renderer now uses `useCurrentFrame` inside bounded caption sequences, a stable composition component, recorded step timestamps, and the actual footage dimensions and duration. See [Remotion frame timing](https://www.remotion.dev/docs/use-current-frame).
- The deadline helper used a 5ms polling interval to keep a test alive. Cancellation is now event-driven; the test uses a referenced timer. Success, failure, pre-aborted work, and late rejection are covered without adding runtime polling to every model call.
- The recorder used nonexistent region selectors, swallowed failed navigation/answers, and renamed WebM to MP4 without transcoding. It now uses existing controls, fails on incomplete steps, cleans up browsers, preserves real WebM, and renders real MP4 through Remotion. See [Playwright video lifecycle](https://playwright.dev/docs/videos).
- New “connected/related” intent matching was too broad for single subjects. Positive connection queries and negative “connected devices”/“related work” examples are covered, along with shared-source-only and empty-connection answers.
